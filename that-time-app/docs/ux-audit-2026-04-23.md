# UX Audit — Service Creation Flow
**Date:** 2026-04-23
**Persona:** Busy salon owner, moderate tech comfort, first-time setup of a new service
**Task:** Create "Hot Stone Massage" with pricing, staff, and advanced options (variants, products, related services)
**Scope:** Full creation wizard → service detail → Variants → Products → Related Services

---

## Summary

The core 4-step wizard is strong and well-paced. The visual language is consistent throughout. The biggest friction sits at the boundary between the wizard and the advanced modules — some configuration gaps slip through, discoverability of lower modules is poor, and a couple of editors leave the user without enough context to know what they're configuring.

**Click count to a saved service (basics only):** ~9 taps — competitive  
**Decision points:** 4 (type, category, staff, price) — appropriate  
**Dead ends encountered:** 0 on the main path  
**Would I come back?** Yes — fast enough that a second service would feel easier. The "You can change this later" reassurance on step 1 removes a lot of early anxiety.

---

## Strengths

### Wizard pacing is excellent
4 steps is the right depth. Each screen has one clear job. The step indicator dots and "Step X of 4" label give constant orientation. The back arrow replacing the X on steps 2–4 is a subtle but correct detail.

### Step 4 quick-select duration chips
Pre-selecting 1h and offering 15m / 30m / 45m / 1h 30m / 2h chips means most users never touch the number input. This is the single fastest interaction in the entire flow.

### Cancellation policy sheet
Clean radio list, 24h pre-selected as a sensible default, and the helper text "Clients must cancel at least this far ahead to avoid charges" explains the consequence without jargon. Pattern works perfectly.

### Variants empty state copy
"Offer the same service in different ways — by duration, staff, time, or place." is the best copy in the app. It immediately answers "what even is a variant?" before the user has to ask.

### Products catalog picker
Grouped by category with catalog prices shown as reference. Search bar at the top. Clean checkbox rows. This is the right model for a catalog that will grow over time.

### Products editor — required toggle helper
"Client must pick one" / "Client can skip" / "Client must pick at least one" updating live as selection type and required state change is genuinely useful. No guesswork about what the toggle means for the client experience.

## Issues

### Medium — No location type set, wizard silently continues
**Where:** Step 2 of 4 (Locations)  
**What:** All three toggles (In-salon, Mobile, Remote) are off by default. The Next button is fully enabled with nothing selected. A user who doesn't notice can complete the entire wizard and publish a service with no delivery method configured.  
**Impact:** The service detail page shows "Add locations" as a CTA, which is easy to miss once you're looking at a complete-looking service card.  
**Fix:** Require at least one toggle before Next enables, or add an inline warning on attempt: "Pick at least one way to offer this service."

### Medium — Service type defaults to "Bundle" after wizard
**Where:** Service detail header after creation  
**What:** The created service shows "Massage · Bundle" — it should be "Massage · Service". The type selection screen was presented first, but clicking anywhere other than the type cards (e.g. the icon area) navigated into the wizard without recording a type choice, leaving the default as Bundle.  
**Impact:** Low in a prototype, meaningful in production — Bundle likely has different booking logic than Service.  
**Fix:** Ensure type is always set explicitly before the wizard starts. Default to "Service" if the picker is bypassed.

### Medium — Lower advanced modules hidden below the fold
**Where:** Service detail page, Advanced section  
**What:** Variants and Products appear immediately. Related services, Resources, Forms, and Service settings are only visible after scrolling past the photo strip — which isn't obvious on a phone with a sticky Publish footer.  
**Impact:** A user who fills in basics and immediately taps Publish will never discover Related services, Forms, or Resources.  
**Fix:** Consider collapsing Photos into a single "Add photos" row (like the other modules), so all 6 advanced modules fit on one scroll without the photo strip consuming vertical space.

### Medium — Related Services editor: no mode or discount visible
**Where:** `/service/related/new`  
**What:** The screen only shows a service picker. There's no way to set suggest vs. discount mode, add a discount amount, or add a note — the fields that give this feature its value. The Save button appears at the bottom with no indication of what configuration will be saved.  
**Impact:** High — a user completing this screen doesn't know what the "suggestion" will look like to clients. This is the flow the user already identified for the wizard upgrade.  
**Fix:** Multi-step wizard (already planned): Step 1 = pick services, Step 2 = set mode + discount, Step 3 = add note + preview.

### Low — Duration variant subtitle truncated in sheet
**Where:** "What kind of variant?" bottom sheet  
**What:** Duration shows "Different lengths of the same servi..." — truncated mid-word.  
**Fix:** Shorten to "Different durations, same service" — fits on one line.

### Low — Duration tiers both default to 60min
**Where:** Duration variant editor  
**What:** When "Add another tier" is tapped, Tier 2 copies the same 60min / £0 defaults as Tier 1. The whole point is to offer *different* durations, but there's no visual nudge that Tier 2 should be a different length.  
**Fix:** Auto-increment the second tier duration (e.g. Tier 1 = 60min, Tier 2 = 90min) or add placeholder text like "e.g. 90".

### Low — Variant staff restriction shows all staff, not service staff
**Where:** Duration editor → Only available when → Specific staff  
**What:** All 6 business staff appear in the restriction list, even if only 2 are assigned to this service. A user could restrict a variant to Jordan Lee (Colourist) who can't actually deliver this service.  
**Fix:** Filter the restriction list to only staff already assigned to the service in Step 3 of the wizard.

### Low — Dev stub text visible on services list
**Where:** Services list (`/`)  
**What:** "Stub list — tap + to start the service creation flow." appears as visible body text below the service cards.  
**Fix:** Remove before any user testing or demo.

## One thing that would make this twice as easy

**Surface the service type confirmation at the end of the wizard, not the start.** Most salon owners don't think in terms of "Service vs Class vs Bundle" — they think "I want to add a massage." Asking the type upfront adds cognitive load before they've even named the thing. Asking "Is this a one-on-one appointment, a group session, or a bundle?" at the Review/Confirm step (after they've described it) would feel more natural and produce fewer miscategorised services.
